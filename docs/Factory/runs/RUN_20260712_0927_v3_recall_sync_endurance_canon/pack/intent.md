## Purpose
Bring the local Factory V2 build-support recall contract up to the approved direct-source repair behavior, then repair active V3 canon that conflates successful mission completion with elapsed-duration evidence.

## Goal
Produce an execution-ready, bounded change that makes weak-recall repair deterministic and makes the `V3-OP-003` endurance claim precise: Factory V3 should preserve governance and work quality for missions that naturally require up to roughly four hours, while missions must finish as soon as their objectives and verification are complete.

## Source Requirements
- R1 [SOURCE: active user clarification, 2026-07-12] Four hours is a maximum capability target, not a required run duration; shorter correct runs are acceptable and must not drift or lose quality if work naturally lasts longer.
- R2 [SOURCE: `factory-starter-kit` commit `06646d7`] Generated `WEAK` recall may proceed only through a constrained `REPAIRED_DIRECT_SOURCE_CHECK` backed by direct local-source evidence.
- R3 [SOURCE: `AGENTS.md`] V3 remains advisory-only except for the existing optional `V3-OP-001`; no runtime authority, required gates, routing, telemetry enforcement, or V2 removal is allowed.
- R4 [SOURCE: `docs/Factory/v3/V3_OP_003_DECISION_PACK.md`] `V3-OP-003` remains `NO PROMOTION YET`; evidence and explicit human release approval are required before promotion.
- R5 [SOURCE: `docs/Factory/v3/ADAPTIVE_MISSION_CONTROL.md`] Complete when the objective and verification are satisfied; do not pad work to meet a size target.

## Principles
- Treat upstream synchronization as behavior transfer, not blind file copying.
- Preserve repository-specific V2 build-support wording.
- Separate mission outcome from capability-evidence coverage.
- Optimize for quality continuity, authority continuity, and verification continuity rather than elapsed time.
- Preserve historical evidence; repair only active summaries, gates, and current recommendations.
- Apply SIMPLE-CODE-GATE to validator changes.

## Acceptance Criteria
- AC1: The local context-recall template, orchestration contract, and stage contracts describe the same direct-source repair path as upstream commit `06646d7`, adapted only for local V2 build-support context.
- AC2: Stage A and pack validators accept a valid repaired report and reject unrepaired, missing-source, external-source, or materially unresolved repairs.
- AC3: Focused repair tests, full unit discovery, knowledge lint, Python compile checks, and existing V3 advisory fixture checks pass.
- AC4: Active canon says mission completion is quality/evidence based, not duration based.
- AC5: Active canon says shorter successful missions pass, while they may leave the upper endurance envelope insufficiently evidenced.
- AC6: Active canon defines endurance degradation signals: objective drift, scope/authority drift, stale-state continuation, verification degradation, checkpoint/re-entry failure, evidence degradation, or lower late-run quality.
- AC7: No text encourages padding, artificial waypoints, call inflation, or time-band pursuit after completion.
- AC8: `V3-OP-003` remains `NO PROMOTION YET` with all existing exclusions intact.
- AC9: Completed template/fixture work is removed from active next-gate lists, and current version/status pointers agree.
- AC10: The V2 synchronization is completed and verified before V3 canon edits begin; failure in the first slice halts the second.
- AC11: Only behavior attributable to upstream commit `06646d7` is transferred, with local V2 build-support wording retained.
- AC12: Historical run artifacts and human decision records are not rewritten; any changed interpretation is stated in current canon.
- AC13: Canon does not claim that four-hour endurance is already proven; shorter successful evidence and upper-envelope evidence coverage remain separate.
